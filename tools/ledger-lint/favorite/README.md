# favorite 域台账自检（ledger self-check）

机器化回答两个问题：**台账是不是「最新」** / **台账是不是「全」**。

```bash
python3 tools/ledger-lint/favorite/check-ledger-selfcheck.py
python3 tools/ledger-lint/favorite/check-ledger-selfcheck.py --json
```

退出码：`0` = 无门禁级问题 · `1` = 有门禁级问题 · `2` = 工具自身出错。

## 为什么要它

台账是**给人读**的，但「最新 / 全」是**可机检**的。人工台账会积累三类**静默**缺陷：

| 缺陷 | 为什么人工容易漏 |
|---|---|
| 跨文件章节引用指错（改标题号后没人发现） | 两份文件要同时打开才看得出来 |
| 编号被引用但没登记（`DEV-FAV-*` / `PIT-FAV-*`） | 引用处看着像结论，其实没有登记条目 |
| Go 侧新增了源文件但台账没跟上 | 台账是**按行为**写的，文件是**按目录**长的 ⇒ 两者不会自动对齐 |

前两轮体检（第九 / 十轮）都是手工查 ⇒ 代价高且不可复跑 ⇒ 本工具把那套人工动作固化成守门。

## 机检三类

| # | 检查 | 门禁级 | 逻辑 |
|---|---|---|---|
| ① | **章节指针** | ✅ | `§x.y` 必须落到目标文件**真实存在**的小节 |
| ② | **编号闭合** | ✅ | `DEV-FAV-*` / `PIT-FAV-*` 被引用 ⇒ 必须有定义处（标题行或表格首列） |
| ③ | **Go 源文件覆盖** | ✅ | Go 侧 favorite 每个**非测试**源文件 ⇒ 台账里必须有落点（basename / 相对路径 / 全路径任一命中） |

另有 **1 类提示级**：裸行号锚点（形如 `` `:48-50` ``）——
**提示级不是门禁**，因为表格里有语境列时裸行号是可接受的简写（判定标准见下）。

## 误报处理（**工具的第一版必须先修再信**）

| 误报类 | 处理 |
|---|---|
| 正文里裸写的路径（如 ``DRIFT/favorite/rpc.md`` §5-U1``）被判死链 | 只有 **markdown 链接** ``[..](path.md) §x.y`` 才做文件级解析；裸路径是「位置描述」，不判 |
| 指向根 `AGENTS.md` / 三个共享 `_INDEX.md` 的引用被判死节 | 把这 4 个**外部目标**纳入索引，按**真实标题**判定 |
| RAG 侧 `target/` 下的 protoc 产物被算成源文件 | 生成代码不计入覆盖检查 |
| 表格里**有语境列**的裸行号（列头已写「RAG（`FavoriteController`）」）被判问题 | 裸行号降级为**提示级**；无语境才需人工修 |

⚠️ 本工具的第一版也踩了坑（正则漏捕获组导致崩溃、`FILES_REF` 定义顺序颠倒）
⇒ **先修工具再信工具**；且第十轮那 6 条「Go 文件未落点」结论是
**工具与人工双向独立得出**的（两边结论一致才算数）。

## 边界

- ✅ 能答：**引用有没有断** / **编号有没有漏登** / **文件有没有漏看**。
- ❌ **不能**答「**行为全对**」——
  ① 只保证「没有文件被漏看」，不保证「看对了」；
  ② 不检查**行号是否指对了那一行**（越界检查必要不充分，见
  [`docs/Pitfalls/favorite/rpc.md`](../../../docs/Pitfalls/favorite/rpc.md) **PIT-FAV-RPC-011**）；
  ③ 不覆盖**共享面**（`docs/DRIFT/_INDEX.md` / `_MANIFEST.json` / `AGENTS.md` / `_cross/`）。

# 🆕 第二件：`check-ledger-vs-reality.py` —— **「台账 vs 实际」复核**

```bash
python3 tools/ledger-lint/favorite/check-ledger-vs-reality.py
```

退出码：`0` = 无门禁级不一致 · `1` = 有门禁级不一致 · `2` = 工具自身出错。

## 它与上面那个工具的分工

| 工具 | 管的是 | 举例 |
|---|---|---|
| `check-ledger-selfcheck.py` | **台账之间** | 章节指针断没断、编号登没登、Go 文件漏没漏 |
| `check-assertion-sources.py` | **代码注释里** | `文件:行号` 锚点能不能解析、行号在不在范围内 |
| **`check-ledger-vs-reality.py`** | **台账说的 ⇄ 仓库实际的** | 「8 个测试类 / 94 例」这两个数字**现在还成立吗**？「13 个模块缺 grpc-inprocess」**现在还成立吗**？ |

## 为什么要有第三层

台账里最危险的断言不是「指针指错」（那个有自检兜底），而是**「数字」**：

- 「6 个测试类 / 89 例全绿」—— 代码加了测试类、例子加了用例 ⇒ **数字过期**，
  而台账读起来**完全通顺** ⇒ **没有任何工具会响**；
- 「13 个别域模块缺 grpc-inprocess」—— 别的域修了几个 ⇒ **条数过期**。

2026-10-25 第十五轮盘点**当场**抓到两处（测试计数 + 跨域清单条数），
其中跨域那条**方向都是错的**（把「没声明」当成缺陷）⇒ 详见
[`docs/DRIFT/favorite/rpc.md`](../../../docs/DRIFT/favorite/rpc.md) **§24.4**。

## 做法（与其它工具的关键区别）

**断言从台账正文里抽**（不把「真相」写死在工具里）⇒ 再**独立**从仓库算实际值 ⇒ 逐条比对。
⇒ 台账一旦改了说法，工具会**跟着改口径**，而不是拿旧真相去硬套。

## 门禁 / 提示的分级

- **门禁级** = 实际值**无歧义**（文件数、定义数、pom 扫描、git diff、常量）⇒ 不一致即红；
- **提示级** = 实际值**有歧义**（用例数：源码 `@Test` 注解 ≠ surefire 报告 ——
  注释里的示例代码、`@Testcontainers` 误匹配都会让两者不等）⇒ **只报差异不判死**
  （依据：`docs/Pitfalls/_cross/testing-pitfalls.md` 的「陈旧 surefire 报告静默抬高测试计数」）。

## 它现在查哪些断言（12 项）

| # | 断言 | 级别 |
|---|---|---|
| ① | favorite-api **测试类数** | 门禁 |
| ② | favorite-api **用例数** | 提示 |
| ③ | **favorite-rpc 测试类数**（🆕 第十六轮） | 门禁 |
| ④ | **favorite-rpc 用例数**（🆕 第十六轮） | 提示 |
| ⑤ | 已签字偏离条数 | 门禁 |
| ⑥ | 🏷 候选条数 | 门禁 |
| ⑦ | grpc-inprocess 缺失（可执行应用模块） | 门禁 |
| ⑧ | `RANDOM_PORT` 暴露面（全仓） | 门禁 |
| ⑨⑩ | 端口段（Java 侧 / 探针侧 ×2） | 门禁 |
| ⑪ | 台账引用的探针目录是否都存在 | 门禁 |
| ⑫ | 共享面零改动 | 门禁 |

🆕 **③ / ④ 为什么加**（第十六轮）：
第十六轮给 favorite-rpc **新增了一个测试类**（成功路径探针）⇒ 按
**PIT-FAV-RPC-022**（「台账里最危险的断言是数字」），
凡是**可枚举、可数出来**的断言都要有一条**能复跑的机检**
⇒ 只改台账不改工具的话，下一个人再加一个测试类就会**又**过期一次，
而**什么都不会响**。

⚠️ **抽取措辞是刻意收窄的**：③ / ④ 锚定的是 §0 摘要行里
`favorite-rpc：**N 个测试类 / M 例**` 这一段**唯一**措辞
（不是泛匹配「N 个测试类」）⇒ 否则会命中旧章节里的旧口径 ⇒ 报一个假的差异。

② 把 §9.3 的端口段改成 `31300–31399` ⇒ **EXIT=1**；还原 ⇒ **EXIT=0**。
🆕 第十六轮：③ 把 §0 的 favorite-rpc 测试类数改成「13 个」⇒ **EXIT=1**；还原 ⇒ **EXIT=0**。

## 边界

- ✅ 能答：**台账里的事实断言还成立吗**。
- ❌ **不能**答「**行为全对**」—— 它只比对**台账与仓库的一致性**，
  不验证任何一方本身对不对（行为对错由 §3.1 的 Go ⇄ RAG 对照负责）。
- ⚠️ **抽取依赖措辞**：断言的**措辞**被大改时，正则可能抽不到 ⇒ 工具会报
  「台账里找不到断言」（**不静默放过**）⇒ 那时该改的是**正则**或**台账措辞**，
  而不是忽略这条红。
