#### 🔴🔴 本轮实测出的**模式级缺陷**（必须记，因为它改变了 P0 #8 的判据）

> **子 agent 用真 `SpringApplication` + 真 ConfigData 流程实测**：
> ① **变量没设** ⇒ Spring 的 `@ConfigurationProperties` 绑定器**不报错**，而是把**占位符原文** `"${USER_JWT_SECRET}"` **当成值绑上去** ⇒ 应用**照常启动**，而这个「密钥」是**仓里公开的一串字符** ⇒ 🔴 **比空密钥更危险**（HMAC 密钥公开 ⇒ 谁都能伪造 token）。
> ② **变量设了但值是空串** ⇒ `PropertyPlaceholderHelper` 把空串当**合法值** ⇒ 应用带着**空签名密钥**正常起来。
>
> ⇒ **「去掉 yaml 默认值」只堵住了一半** ⇒ 另一半必须由代码堵：守卫必须**额外拒绝「未解析的占位符字面量」**（`Pattern.compile("^\\$\\{[^}]*\\}$")`）。
> ⇒ **且**多个 `@PostConstruct` 的**执行顺序不由 JVM 规范保证**（实测两次运行报错顺序不同）⇒ 必须改成**单一有序入口**。

> ✅ **该模式级缺陷已全仓修完**：4 个旧模式模块（`article-api` / `comment-api` / `favorite-api` / `like-api`）已改为**单一有序入口 + 拒绝未解析占位符字面量** ⇒ 每模块 **4 条变异精确转红** ⇒ 另 compose **6 处 `:?`**（缺变量 ⇒ 拒绝渲染，实测 **EXIT=1**）⇒ 守门 `tools/difftest/check-no-prod-secrets.py` **EXIT=0**（未豁免命中 **0**）⇒ ⇒ **P0 #8 ✅**。
> ⚠️ **残留（已登记 · C 类 · 不阻断）**：9 个 rpc 模块的**部署凭据**默认值（`F-6` / `A-5`）⇒ **归属订正为域内**（原写「归 G4」是错的）⇒ 列入 **R5**。
