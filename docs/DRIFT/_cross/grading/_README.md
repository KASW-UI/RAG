> **本目录是「派生层」的输入之一**，不是台账。
> 生成器 = [`tools/ledger-derive/derive-stage1.py`](../../../../tools/ledger-derive/derive-stage1.py)
> （读它 ⇒ 规则号 **U5-O**；优先级**最高**，压过台账表格里的历史「阶段归属」列。）

## 一、为什么另立这一层（不直接改台账）

台账里绝大多数条目是**表格行型**（实测：第 1 轮 129 条待定级条目里 **71 条是表格行**），
而扫描器里**表格行的「段」= 该行本身** ⇒ 想给表格行挂定级只有三条路：

1. **塞进单元格** —— 但表格通常**已有「阶段归属」列** ⇒ `U5-0`（表格定级）
   **优先于** `U5-f`（条目正文声明）⇒ **塞了也不生效**；
2. **改表格结构**（加一列）—— 破坏原台账，且各域表型不一 ⇒ 不可取；
3. **另立叠加层** —— 不动原表、零破坏、逐条可回源 ⇒ **采用**。

⇒ **台账原文一律不动**；定级结论落在这里，派生层重生成后自动拾取。

### 1.2 同源判定（`_samesrc-*.md`）—— **「同一件事」还是「编号撞了」**

⚠️ **2026-10-30 用户拍板**：派生层的**条目身份 = 编号 + 所属域目录** ⇒ 台账用**裸编号** ⇒
同一个编号在不同域**通常**指的不是同一件事 ⇒ 默认**拆开**（消除「一个域的定级被继承到另一个域」的串味）。

⇒ **但**有一批编号是**「同一件事跨域登记」**（别的域引用了同一个条目：汇总表 / `vs-common.md` /
准入表 / 「域内部分已修」的补记章节）⇒ 拆开后**同一件事会在两个域各判一次** ⇒ 可能**一份读到旧快照（🔴）**
⇒ **虚增一条假缺口**。

⇒ 故加**同源判定**层：`_samesrc-W*.md`（**人工逐条判定**，三档：`同一件事` / `不同的事` / `无法判定`）
⇒ 由 `tools/ledger-derive/gen-identity-groups.py` 生成
[`tools/ledger-derive/identity-groups.txt`](../../../../tools/ledger-derive/identity-groups.txt) ⇒ **仍合并成一条**。

⚠️ **关系表的粒度 = 节点（编号, 所属域）**，不是裸编号 ⇒ 两类同源**统一处理**：

| 类型 | 例 | 为什么要合并 |
|---|---|---|
| **同编号跨域** | `E65`@favorite ≡ `E65`@global | 别的域引用了同一条目 ⇒ 拆开 ⇒ 一份读到旧快照 ⇒ 虚增假缺口 |
| **不同编号别名** | `DRIFT-CF-001`@common ≡ `CF-001`@common | 台账**同一件事登记了两次**（长编号 + 短编号）⇒ 拆开 ⇒ 虚增两条 |

⇒ ⚠️ **「同一个编号在组内的域」与「组外的域」必须分开** ⇒ 键是 `(编号, 域)`：
例如 `CF-001` 与 `DRIFT-CF-001` 在 `common` 域合并，但 `CF-001` 在别的域若是**撞号**则**不合并**。
⇒ ⚠️ **不得按「编号族」通配** —— 同一族里既有同源的也有撞号的。

⚠️ **本体位置怎么变成「节点」**（机械反查，不手填）：判定表第 5 列写 `路径:行号`
⇒ `resolve_pointer` 反查该行落在哪个条目段 ⇒ 得 `(编号, 域)`。
⚠️ **第 5 列的路径序位有语义**：**第 1 个 = 本体**；其余 = **引用方**。
⇒ 反例（实测）：`E38`@global 的第 5 列 = 「本体＝global `_README.md:388`；引用方＝users `user/rpc.md:832` /
`admin/rpc.md:3699` / comment `vs-common.md:28`」⇒ 其中 `:3699` 那一行**同时**被 `E65` 与 `E38` 引用
⇒ 反查落到**另一个编号** ⇒ 若把它也当本体 ⇒ 建出 `E38@global ≡ E65@users` 这条**假边**。
⇒ 规则：**第 1 个路径无条件建边**；其余路径**仅当反查编号 == 当前编号**才建边（异编号只认第 1 个）。

⚠️ **「无法判定」不进同源表** ⇒ 派生层**不猜** ⇒ 那些编号保持拆开，并在派生层 §4.6「跨域同编号登记」对照表里露出。
⚠️ **「未建边」≠「有缺陷」** —— 实测 3 条未建边全部**非缺陷**：
`G-19`@hot（**全仓唯一**）· `H-1`@hot（**同域两处**登记）· `T-17`@global（**同域两处**登记）。
⇒ 生成器会把该编号的**实际登记位置**一并列出，供人复核。
⚠️ **本目录的文件名以 `_` 开头 ⇒ 扫描器跳过**（`_` 前缀 = 说明/判定文件，不是数据）⇒ 不会自噬。

## 三、表格格式（列固定，顺序不可变）

| 编号 | 归属 | 优先级 | 阻断阶段一 | 依据 | 核对日期 |
|---|---|---|---|---|---|
| E9 | C | P2 | 否 | Go `service/global/xxx/x.go:120`（原文语义…）vs RAG `service/global/xxx/X.java:88`（现状…）⇒ 差异仍成立 | 2026-10-30 |

| 列 | 取值 | 硬性要求 |
|---|---|---|
| **编号** | 台账里的**原编号**（如 `E9` / `DRIFT-MSG-012` / `SD-2026-10-24-CAND-01`） | 必须与台账里的写法**逐字一致**（否则派生层对不上） |
| **归属** | `A` / `B` / `C` / `D`（可带后缀说明，如 `A（阶段一准入阻断项）`） | 必须是 A-D 之一，否则**整行丢弃** |
| **优先级** | `P0` / `P1` / `P2` / `P3` | 留空 ⇒ 派生层按状态回落 |
| **阻断阶段一** | `是` / `否` | 留空 ⇒ 派生层按「A ⇒ 是」回落 |
| **依据** | **必须含 Go 侧 `*.go:行号` + RAG 侧 `*.java:行号` + 结论** | ⚠️ **缺任一侧 ⇒ 整行丢弃**（否则「定级」就是无出处的断言） |
| **核对日期** | `YYYY-MM-DD` | 本轮统一 `2026-10-30` |

## 四、判据（规范来源 = [`docs/twoStage.md`](../../../twoStage.md) §10）

### 4.1 阶段归属（A-D）

| 类 | 含义 |
|---|---|
| **A** | 阶段 1 准入阻断项 —— 不处理就无法通过阶段一验收 |
| **B** | 阶段 1 竞争力补强项 —— 形成可信的技术亮点与验证闭环 |
| **C** | 阶段 2 最终工程建设项 —— 业务语义恢复 / 生产工程机制 / 最终验证 |
| **D** | 经分析确认**可不实现或不适用** —— **必须写明理由** |

> ⚠️ **A-D 描述「阶段归属」，P0-P3 描述「严重程度」，两者不能互相替代**（§10 原文）。
> ⚠️ **D 类不是「小事」的代名词** —— 「经分析确认」+「明确理由」是 D 类的**构成要件**；
> 「还没查」**不构成 D 类**，那是「待回源」⇒ 归 C（阶段 2 补齐）或按实际情况归 A/B。

### 4.2 优先级（P0-P3）

- **P0** 明确的严重安全 / 数据完整性 / 业务正确性问题 ⇒ 应阻止阶段验收
- **P1** 关键可靠性 / 安全 / 恢复 / 容量风险 ⇒ 需优先处理
- **P2** 重要工程缺陷 ⇒ 近期修复
- **P3** 改进项 ⇒ 不构成当前验收阻断条件

### 4.3 阻断阶段一

= 「该条目是否阻断阶段一验收」⇒ **是 / 否**。
⚠️ **A 类默认「是」，但可以显式写「否」**（例如 A 类但只在特定部署形态下成立）。

## 五、结论三态（**不许二选一**）

「依据」列的结论必须落在下面三态之一，**不许含糊**：

| 结论 | 含义 |
|---|---|
| **差异仍成立** | 两侧行为确实不一致 |
| **差异已消失** | 台账记的那条**已经不存在了**（已被修掉 / 从未被引入）⇒ **这是重要发现，要写清怎么消失的** |
| **无法证实** | 两侧当前都读不到足够的依据来判定 ⇒ **不许猜**，写「无法证实 + 缺什么」 |

## 六、纪律（本层的硬约束）

1. **原值保留** —— 本目录**不修改**任何台账原文；台账的订正/回写由主线收口时统一做。
2. **不许编造行号** —— Go 与 RAG 两侧的行号必须**实际打开文件确认过**；
   找不到就写「无法证实」+ 缺什么，**不许填一个看起来合理的行号**。
3. **一条差异 ≠ 一个缺陷** —— 两侧写法不同但**行为相同** ⇒ 结论是「差异已消失」或「不适用」，
   **不许**直接判成缺陷。
4. **R 与 E 不可互推** —— 「RAG 有这条代码」**推不出**「Go 也有」；反之亦然。
5. **已签字偏离（`Intentional_Deviations`）** ⇒ 状态是「✅ 仍成立」，两侧确实不一致
   ⇒ 这是**决策不是缺陷** ⇒ 阶段归属通常归 **D**，**不要**当成待修问题。
6. **指针能解析 ≠ 结论为真** —— 依据里的行号必须**真的支持**你写的结论。

## 七、🆕 派生层自身修掉的 3 个 bug（2026-10-30）—— **「跑绿 ≠ 对」的又一次现身**

⚠️ 这 3 个都在**派生层**（不是台账）⇒ 它们的共同形态是：**数字漂亮、内容全错**。

| # | 症状 | 真因 | 证据 | 修法 |
|---|---|---|---|---|
| ① | **任务/未决项 ↔ 条目的指针关联全部失效** | `_link_ids_by_pointer` 的正则要求 `docs/` 前缀，而 `line_index` 的键是**相对 `docs/`** 的路径 ⇒ **键永远对不上** | 实测 **817 条指针命中 0 条** ⇒ 修复后 **3282 条指针命中 2914 条（88%）** | 正则改为 `docs/` 前缀**可有可无**；新增 `resolve_pointer`（多根 + 多写法） |
| ② | **指向表格行的指针解析成「前一个编号」** | 反查只按「条目段」⇒ 表格行的指针落到**段首那个编号**上 | `users/stage1-admission.md:530` = `S1-FOLLOW-013` 那行，却解析成 `S1-FOLLOW-011` ⇒ **同源组建错边** | 新增**精确行索引**（`start == end`）+ **表头列名判定**（表头首格须是「编号/条目/ID」）⇒ 表格行按**自己的首格**解析 |
| ③ | **建出假同源边** `E38@global ≡ E65@users` | 判定表第 5 列含**本体 + 引用方**多路径 ⇒ 把引用方也当本体 | `:3699` 那一行**同时**被 `E65` 与 `E38` 引用 ⇒ 反查落到另一个编号 | **第 1 个路径 = 本体**；其余路径**仅当反查编号 == 当前编号**才建边 |

⚠️ **共同教训**（与「零命中是假信号」同族）：
① **恒空的判据不会报错** —— 它只会让某个数变成 0 ⇒ **必须拿已知样例反测**；
② **「解析到某个东西」不等于「解析到对的东西」** —— 反查要**逐条核对反查结果**，不能只看命中率；
③ **多值输入里的「序位」常常带语义**（本体 vs 引用）⇒ 不能一视同仁。

⚠️ **另外还查到 1 处「漏识别」（本轮**未**改，另立一轮）**：
**表格行型条目**的首格带 emoji / 加粗时（如 `| 🆕 **\`S1-FOLLOW-007\`** |`）⇒ 旧正则要求首格**立刻**是编号 ⇒ **漏识别 31 行**。
⚠️ 本轮**刻意不改** —— 改它会**全量重算所有数字**（条目数 / 定级数 / 真缺口口径）⇒ 需独立一轮 + 逐条人工核对那 31 行。
⇒ 实测那 31 个编号**在派生表里已由别处登记** ⇒ 当前**不影响施工单派单**（但**不可**当「已修」）。
