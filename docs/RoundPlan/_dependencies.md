# 阶段一 RoundPlan · 依赖说明（规范 §11.4）

## 口径说明

1. **本文件只描述依赖关系，不执行任何整改**（规范 §一.6 / §一.7）⇒ 所有「依赖」都是**计划态**的。
2. **任务 ID 口径** = `P<轮>-T<序号>`（例 `P1-T01`），与 [`_task-universe.md`](_task-universe.md) 一一对应；原始编号（`E65` / `X-6` / `P0 #4` / `R5-F*` / `S1-*`）**原样保留**，不与计划 ID 混用。
3. **「前置」的判定标准** = 被依赖任务先产出**可被下游消费的可检查产物**（落表 / 活体证据 / 改判后的状态 / 台账回填），**不是**「先开始」。
4. **同一轮内的任务编号连续** ⇒ 若某轮只完成子集，该轮下游一律视为**未解锁**（不允许「部分完成即放行」）。
5. **轮次编号 = 计划轮次**（`Round 1`~`Round 7`），**不等于**历史 `Round-0`~`Round-5` 文件（后者已归档，见 [`_migration.md`](_migration.md)）。
6. **条件触发机制**（`CT-01` / `CT-02`）**不是正常轮次** ⇒ 它们不排在 DAG 上，只在触发点插入；`CT-01` 会把受影响的验收与 `P6-T01` 重跑，`CT-02` 只定级 + 记录，**不得**升级为新的强制整改任务。
7. **本文件里的一切「绿 / 不绿」都是判据，不是结论** ⇒ 阶段一结论由 `P7-T01` 的 T7 一次给出（`docs/RoundPlan/round-07/README.md` §5.3.1）。
8. **写权归属**一律以 `AGENTS.md` §5.3b/§5.3d/§5.3e/§5.3f 与 `docs/DRIFT/global/lanes/_PROTOCOL.md` §二 为准，本文件只做**引用与冲突提示**。
9. **行号引用均已实查**（读的是当前 `do-my-own-gh` 工作区）；台账行号若在执行期漂移，以**任务落点文件**为准。
