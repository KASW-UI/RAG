# favorite 域台账自检（ledger self-check）

机器化回答两个问题：**台账是不是「最新」** / **台账是不是「全」**。

```bash
python3 tools/ledger-lint/favorite/check-ledger-selfcheck.py
python3 tools/ledger-lint/favorite/check-ledger-selfcheck.py --json
```

退出码：`0` = 无门禁级问题 · `1` = 有门禁级问题 · `2` = 工具自身出错。

## 为什么要它

台账是**给人读**的，但「最新 / 全」是**可机检**的。人工台账会积累三类**静默**缺陷：

| 缺陷 | 为什么人工容易漏 |
|---|---|
| 跨文件章节引用指错（改标题号后没人发现） | 两份文件要同时打开才看得出来 |
| 编号被引用但没登记（`DEV-FAV-*` / `PIT-FAV-*`） | 引用处看着像结论，其实没有登记条目 |
| Go 侧新增了源文件但台账没跟上 | 台账是**按行为**写的，文件是**按目录**长的 ⇒ 两者不会自动对齐 |

前两轮体检（第九 / 十轮）都是手工查 ⇒ 代价高且不可复跑 ⇒ 本工具把那套人工动作固化成守门。

## 机检三类

| # | 检查 | 门禁级 | 逻辑 |
|---|---|---|---|
| ① | **章节指针** | ✅ | `§x.y` 必须落到目标文件**真实存在**的小节 |
| ② | **编号闭合** | ✅ | `DEV-FAV-*` / `PIT-FAV-*` 被引用 ⇒ 必须有定义处（标题行或表格首列） |
| ③ | **Go 源文件覆盖** | ✅ | Go 侧 favorite 每个**非测试**源文件 ⇒ 台账里必须有落点（basename / 相对路径 / 全路径任一命中） |

另有 **1 类提示级**：裸行号锚点（形如 `` `:48-50` ``）——
**提示级不是门禁**，因为表格里有语境列时裸行号是可接受的简写（判定标准见下）。

## 误报处理（**工具的第一版必须先修再信**）

| 误报类 | 处理 |
|---|---|
| 正文里裸写的路径（如 ``DRIFT/favorite/rpc.md`` §5-U1``）被判死链 | 只有 **markdown 链接** ``[..](path.md) §x.y`` 才做文件级解析；裸路径是「位置描述」，不判 |
| 指向根 `AGENTS.md` / 三个共享 `_INDEX.md` 的引用被判死节 | 把这 4 个**外部目标**纳入索引，按**真实标题**判定 |
| RAG 侧 `target/` 下的 protoc 产物被算成源文件 | 生成代码不计入覆盖检查 |
| 表格里**有语境列**的裸行号（列头已写「RAG（`FavoriteController`）」）被判问题 | 裸行号降级为**提示级**；无语境才需人工修 |

⚠️ 本工具的第一版也踩了坑（正则漏捕获组导致崩溃、`FILES_REF` 定义顺序颠倒）
⇒ **先修工具再信工具**；且第十轮那 6 条「Go 文件未落点」结论是
**工具与人工双向独立得出**的（两边结论一致才算数）。

## 边界

- ✅ 能答：**引用有没有断** / **编号有没有漏登** / **文件有没有漏看**。
- ❌ **不能**答「**行为全对**」——
  ① 只保证「没有文件被漏看」，不保证「看对了」；
  ② 不检查**行号是否指对了那一行**（越界检查必要不充分，见
  [`docs/Pitfalls/favorite/rpc.md`](../../../docs/Pitfalls/favorite/rpc.md) **PIT-FAV-RPC-011**）；
  ③ 不覆盖**共享面**（`docs/DRIFT/_INDEX.md` / `_MANIFEST.json` / `AGENTS.md` / `_cross/`）。
