# CI 契约基准（Contract Baselines）

> **本目录是 Java CI 的「语义真值」。**
>
> Go 原始项目（`Sea-RideTheWind_golang`）是**参考基准**，用于提取业务规则、接口契约、
> 错误语义、数据约束。**它不是 CI 的执行对象** —— 本目录里的文件是把它提取出来的
> **机器可读契约基准**，CI 直接读这些基准，与 Java 项目比对。

## 一、为什么要有这个目录

R4（接口契约）/ R5（错误码契约）/ R6（数据库 Schema 契约）三道门需要「真值」。
三种拿真值的办法：

| 办法 | 代价 | 判定 |
|---|---|---|
| A. CI 拉 Go 仓，现场跟 Go 比 | CI 依赖 Go 工具链 + Go 仓库在线可访问 + Go module cache | ❌ **禁止**。Go 不是 CI 执行对象；Go 仓离线/改写就让 CI 失去可重复性 |
| B. CI 拉 Go 仓，比对**结果**（Go 侧探针产物） | 仍需 Go 工具链 | ❌ 同上 |
| C. **把契约提取成基准，固化在本目录；CI 只比对 Java 侧** | 需要一次性的提取 + 人工确认流程 | ✅ **本目录采用** |

办法 C 的关键性质：**提取是离线的、一次性的、可人工审查的；比对是在线的、自动的、纯 Java 侧的。**

## 二、三类基准

| 基准 | 目录 | 格式 | 门 | 比对对象 |
|---|---|---|---|---|
| **Proto 接口契约** | `proto/` | `<domain>.proto`（规范化后的契约文本） | R4 | Java 侧 `<域>-proto/src/main/proto/<name>.proto` 规范化后 |
| **错误码契约** | `errmsg/` | `<domain>.txt`（**两段式**：Go 权威段 + 差异裁定段） | R5 | Java 侧 `tools/errmsg-probe/<域>/java/Probe.java` 实跑产物 |
| **数据库语义约束** | `schema/` | `<domain>.json` | R6 | Java 侧 Flyway 迁移在干净 PG 上重放后的实际 schema |

**共同点**：基准是**契约语义**，不是 Go 源码副本。
Proto 基准已剥离 `option` 块（表达层）；错误码基准的**权威段存的是 Go 侧的值**（不是 Java 现况）；
Schema 基准只记录**必须保持的约束**与**已批准的实现差异**，不记录 Go 的索引命名形态。

### 2.1 🆕 错误码基准的两段式（2026-10-31 返工）

⚠️ **初版基准的 dump 段里存的是 Java 侧探针的输出** ⇒ Go 值只在注释里
⇒ **基准的权威内容其实是 Java 现状** ⇒ 这正是「**禁止以 Java 现状反向定义目标**」所禁止的
⇒ 已返工为两段式：

| 段 | 内容 | 性质 |
|---|---|---|
| `# >>> go-authority >>>` | `GOCONST\|<码>\|<常量名>` · `GOTABLE\|<码>\|<文案>` · `GOFALLBACK\|<文案>` ⇒ **Go 侧权威值**，逐条附 Go 源文件 `文件:行号` + sha256 | **目标（WHAT）** |
| `# >>> deviations >>>` | `DEVIATION\|<段>\|<键>\|<go值>\|<java值>\|<status>\|<依据id>\|<依据出处>\|<理由>` | **差异裁定（逐条）** |

`status` 四态 —— 这是「**不许自行豁免**」的落点：

| status | 含义 | 门禁行为 | 依据要求 |
|---|---|---|---|
| `approved` | 已签字的**有意偏离** | 放行 | 依据 id 必须能在 `docs/Intentional_Deviations/` 的**被引文件**里查到 |
| `closed` | 已销号（证伪关闭）的差异 | 放行 | 依据 id 必须能在 `docs/DRIFT/` 的**被引文件**里查到 |
| `technical` | **技术判定**：Go 侧该形态**不可达** / 两个运行时的**结构性差异** | 放行 | 出处必须含 **Go 侧 `文件:行号`** |
| `pending` | **未经批准 ⇒ 需用户拍板** | **不判 FAIL，但该域不计入 PASS**，且逐条显式报出 | —— |

⇒ 门禁**自证豁免**：`approved` 的依据 id 查不到 ⇒ **FAIL**（不许自行把差异列进豁免）。
⇒ 实测（2026-10-31）：approved **31** / closed **2** / technical **13** / **pending 8**（pending 单列待拍板）。

## 三、基准的来源与审查

每份基准都必须能回答：**这个值是从哪来的、谁确认过。**

1. **提取**（离线，不在 CI 里做）：从 Go 真源对应文件提取候选值。
2. **核对**：逐条与 Go 真源 + 仓内既有台账（`docs/DRIFT/**`）对照，
   确认每条差异是「已批准的实现差异」还是「未解释的漂移」。
3. **固化**：写入本目录，**必须**在文件头写明来源（Go 侧 `文件:行号`）与裁定依据。
4. **审查**：基准变更走 PR，review 时对照来源文件逐条核。

⚠️ **基准变更 = 契约变更**，不是「更新快照」：
改了基准就是在改契约，必须在 PR 里说明**为什么 Go 侧的语义变了，或为什么 Java 侧的实现差异被批准**。

## 四、失败语义

| 状态 | 含义 | 何时出现 |
|---|---|---|
| **PASS** | 基准与 Java 侧实际**逐字节/逐项一致**，检查确实执行了 | 正常 |
| **FAIL** | 检查执行了，发现 Java 侧与基准不一致 | 契约漂移 |
| **BLOCKED** | 环境/依赖不满足，**检查没做成** | 缺 PG 容器 / 缺 Maven 产物 / 基准文件缺失 |
| **NOT_RUN** | 本次未执行该域 | 域不在本次范围（如 `hot` 域无数据库 ⇒ DDL 维度 N/A） |
| **PENDING**（R5 专用） | 存在**已登记但未签字**的差异 | 该域**不得计入 PASS**；逐条显式报出，等用户拍板 |

**BLOCKED / NOT_RUN / PENDING 一律不得计入 PASS。**

⚠️ **两道口径的差别（别混谈）**：
· **门禁的 PASS** = 「未发现**未登记**的漂移」；
· **目标要求清单的 VERIFIED** = 「这条目标要求已被**实际验证达成**」（见 `ci/requirements/README.md`）。
⇒ 两者的差集 = 「**已登记但未签字**」的部分 ⇒ 这部分在门禁里放行（不判 FAIL），
在清单里判 `NOT_VERIFIED`（**不计入 PASS**）⇒ **两处口径都保守，不冲突**。
每个检查器必须自己区分这三者（退出码约定见各脚本头部注释），
不得用「跳过」把环境问题伪装成通过。
