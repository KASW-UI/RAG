# ci/contracts/errmsg/hot.txt —— R5 错误码契约基准（hot 域）· **Go 真源派生**
#
# 【这是什么】
#   R5 错误码契约的**机器可读基准**。CI 用 `ci/scripts/check-errmsg-contract.sh`
#   跑 **Java 半边探针**（tools/errmsg-probe/hot/java/Probe.java）⇒ 把产物当作**被测对象**，
#   与本文件的 **Go 权威段**做**双向**比对。
#
# 【权威性来源 = Go 真源（只读 · 冻结）】
#   Go 真源：Sea-RideTheWind_golang/service/hot/common/errmsg.go
#     · const 块 :33-46 · codeMsg 表 :48-61 · GetErrMsg :76-84
#     · sha256 = f7ce1f812b2547c491d10369b0da779043d8c8cf92a8e9d7b0dc7d5d53f8c976
#   Java 被测：service/hot/hot-common/src/main/java/com/rag/hot/hot/common/errmsg/{HotErrorCode,HotErrorMessages}.java
#
# 【提取方式（离线 · 一次性 · 可复算）】
#   `python3 ci/scripts/extract-errmsg-authority.py --emit hot` ⇒ 本文件的 go-authority 段
#   独立复算：`python3 ci/scripts/extract-errmsg-authority.py --check`（逐字节比对 ⇒ 证明基准确实来自 Go）
#   ⚠️ CI **不拉 Go 仓、不装 Go 工具链、不跑 Go 探针** ⇒ 权威值固化在本目录。
#
# 【两段式结构】
#   # >>> go-authority >>>  —— **Go 侧权威值**（CI 的真值来源）
#       `GOCONST|<code>|<Go 常量名>`（const 块全部常量）· `GOTABLE|<code>|<文案>`（codeMsg 表全部条目）· `GOFALLBACK|<文案>`（GetErrMsg 对未知码的回落 = codeMsg[Error]）
#   # >>> deviations >>>   —— **逐条差异裁定**（Go↔Java 的每一条差异都在这里落笔）
#       DEVIATION|<段>|<键>|<go值>|<java值>|<status>|<依据id>|<依据出处>|<理由>
#       status ∈ approved | closed | technical | pending
#
# 【四类差异状态】
#   approved  —— 已签字（依据 id 必能在 `docs/Intentional_Deviations/` 里查到）
#   closed    —— 已销号/证伪关闭（依据 id 必能在 `docs/DRIFT/` 里查到）
#   technical —— 技术判定（Go 侧该形态**不可达** / 两个运行时的**结构性差异**）
#               ⇒ 依据出处必须给出 Go 侧 `文件:行号`
#   pending   —— **未经批准、需用户拍板** ⇒ **不判 FAIL**，但逐条显式报出，
#               且**该域不得计入 PASS**（门以退出码 3 收口）
#
# 【本域差异台账】 approved=0 · closed=0 · technical=0 · pending=0（共 0 条）
#
#   ⚠️ hot 域 Go 真源有 `GRPCError` / `BizCodeFromError`（`errmsg.go:84-` / `:88-`），但 RAG 的 hot-common **只有码表 + 文案表** ⇒ 本基准**不覆盖** hot 的 wire 载体语义。
#
