# 【本域已批准差异清单】（Go 侧 vs Java 侧 · **逐条** · 共 2 条）
#   ⑴ OBS|obs_ok_status
#        Go   : ok|
#        Java : ok|user_id invalid
#        裁定 : 已登记 · 不可达差异（OBS 段） —— Go 的 `status.Error(codes.OK, msg)` **返回 nil**（grpc-go `internal/status/status.go`：`func (s *Status) Err() error { if s.Code() == codes.OK { return nil } }`）⇒ `status.FromError(nil)` ⇒ **没有 description**；Java 的 `Status.OK.withDescription(msg).asRuntimeException()` 造出来的是一个**非 nil**、code=OK、**带 description** 的 `StatusRuntimeException`。「OK 状态不是错误」是 grpc-go 的 API 形态，grpc-java 没有对应的塌缩。 Go `get_task_logic.go:44`（形态上）；Java `TaskServiceGrpcImpl.java:81-83`。
#   ⑴ OBS|obs_wrapped_status
#        Go   : invalid_argument|outer: rpc error: code = InvalidArgument desc = user_id invalid
#        Java : unknown|outer: rpc error: code = InvalidArgument desc = user_id invalid
#        裁定 : 已登记 · 不可达差异（OBS 段） —— Go 的 `status.FromError`（grpc-go v1.81.1）**用 `errors.As` 穿透包装**找到内层 status ⇒ **保住 code**；但 **description 被换成外层 error 的全文**（`p.Message = err.Error()`）。Java 的 `TaskServiceGrpcImpl` 只认**直接抛出的** `StatusRuntimeException` ⇒ 包装过就落进 `catch (RuntimeException)` ⇒ **code 退化成 `UNKNOWN`**。这是 grpc-go 与 grpc-java 的**结构性差异**。 Go grpc-go `status/status.go` 的 `FromError`；Java `TaskServiceGrpcImpl.java:81-89`。
#

#     · （`throw new RuntimeException("…", e)`），`INVALID_ARGUMENT` 会**当场退化成 `UNKNOWN`** ⇒ 本基准会红。
