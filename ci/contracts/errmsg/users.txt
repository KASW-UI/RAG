# ci/contracts/errmsg/users.txt —— R5 错误码契约基准（users 域）· **Go 真源派生**
#
# 【这是什么】
#   R5 错误码契约的**机器可读基准**。CI 用 `ci/scripts/check-errmsg-contract.sh`
#   跑 **Java 半边探针**（tools/errmsg-probe/users/java/Probe.java）⇒ 把产物当作**被测对象**，
#   与本文件的 **Go 权威段**做**双向**比对。
#
# 【权威性来源 = Go 真源（只读 · 冻结）】
#   Go 真源：Sea-RideTheWind_golang/service/user/common/errmsg/errmsg.go
#     · const 块 :3-36 · codeMsg 表 :38-68 · GetErrMsg :70-76
#     · sha256 = 508a862a52127e0dbfbd0b206b4b121d346cad3213f0f415ab471025929675d1
#   Java 被测：service/users/users-common/src/main/java/com/rag/users/common/errmsg/ErrorCode.java
#
# 【提取方式（离线 · 一次性 · 可复算）】
#   `python3 ci/scripts/extract-errmsg-authority.py --emit users` ⇒ 本文件的 go-authority 段
#   独立复算：`python3 ci/scripts/extract-errmsg-authority.py --check`（逐字节比对 ⇒ 证明基准确实来自 Go）
#   ⚠️ CI **不拉 Go 仓、不装 Go 工具链、不跑 Go 探针** ⇒ 权威值固化在本目录。
#
# 【两段式结构】
#   # >>> go-authority >>>  —— **Go 侧权威值**（CI 的真值来源）
#       `GOCONST|<code>|<Go 常量名>`（const 块全部常量）· `GOTABLE|<code>|<文案>`（codeMsg 表全部条目）· `GOFALLBACK|<文案>`（GetErrMsg 对未知码的回落 = codeMsg[Error]）
#   # >>> deviations >>>   —— **逐条差异裁定**（Go↔Java 的每一条差异都在这里落笔）
#       DEVIATION|<段>|<键>|<go值>|<java值>|<status>|<依据id>|<依据出处>|<理由>
#       status ∈ approved | closed | technical | pending
#
# 【四类差异状态】
#   approved  —— 已签字（依据 id 必能在 `docs/Intentional_Deviations/` 里查到）
#   closed    —— 已销号/证伪关闭（依据 id 必能在 `docs/DRIFT/` 里查到）
#   technical —— 技术判定（Go 侧该形态**不可达** / 两个运行时的**结构性差异**）
#               ⇒ 依据出处必须给出 Go 侧 `文件:行号`
#   pending   —— **未经批准、需用户拍板** ⇒ **不判 FAIL**，但逐条显式报出，
#               且**该域不得计入 PASS**（门以退出码 3 收口）
#
# 【本域差异台账】 approved=0 · closed=2 · technical=0 · pending=0（共 2 条）
#
#   ⚠️ Go 侧的 users 域 = `service/user/`（**user 与 admin 共用同一份 errmsg**）⇒ 本基准覆盖的是这两条链路**共用**的错误码契约。⚠️ users 域的 RAG 侧**没有独立的文案表类**，**枚举本身就是那张表** ⇒ 本域**没有** WIRE / BIZCODE 层（Go 真源也不 import grpc）。
#
