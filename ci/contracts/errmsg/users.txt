# 【权威性来源 = Go 真源（只读 · 冻结）】
#   Go 真源：Sea-RideTheWind_golang/service/user/common/errmsg/errmsg.go

# 【提取方式（离线 · 一次性 · 可复算）】
#   2026-10-31 用 `tools/errmsg-probe/users/run-parity.sh` 跑**双侧对拍**：
#     · Go 半边：把真源 `errmsg.go` 复制进临时模块、与真源**同包**编译后跑
#       （复制件与真源比 sha256，不一致即 exit 2 ⇒ 验的确实是真源）；
#     · Java 半边：`javac` 编译探针 → 跑**真实编译产物**（`<域>-common` 的
#       `target/classes`）⇒ 探针自己**不持有任何码值/文案常量**（否则是「拿 RAG 的值验 RAG 的值」）。
#   本文件 = **Java 侧 dump**（Java 侧应当满足的契约）。
#   ⇒ Go 仓**不需要**在线、Go 工具链**不需要**进 CI 镜像。
#
# 【裁定依据】

# 【层次与规模】
#   CONST(31 个码) + TABLE(31 条文案) + FALLBACK(24 个未登记码)
#     · ⚠️ Go 侧的 users 域 = `service/user/`（**user 与 admin 共用同一份 errmsg**）
#     ·    ⇒ 本基准覆盖的是这两条链路**共用**的错误码契约。
#     · ⚠️ users 域的 RAG 侧结构与其它域不同：`users-common/…/errmsg/` 下**只有 `ErrorCode.java` 一个类**

#     · 查表入口 = `ErrorCode.getMsg(int)`；未知码回落走 `ErrorCode.of(int)` ⇒ `ERROR` ⇒ `"FAIL"`。
