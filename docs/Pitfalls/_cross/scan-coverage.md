# 枚举「全量」本身会漏：路径模式只跨一层 ⇒ 「零命中」被读成「不存在」（2026-10-30 · 合并收口执行者自踩）

> **本文件只记「我以为我查全了，其实没查全」的形态** —— 即：
> 用**路径模式**枚举一批文件，**漏掉了嵌套 ≥2 层的目录** ⇒ ⇒ 零命中 ⇒ ⇒
> 被当成「这个东西不存在」⇒ ⇒ **据此做了决策**（端口分配 / 差异定级 / 有没有载体）。
>
> ⚠️ **共性：它是「静默」的** —— 扫描照常返回、零命中照常打印、结论照常写进台账。
> ⇒ ⇒ **唯一检出手段 = 把枚举到的文件清单打出来，核对「该在的都在不在」**。

---

## PIT-SCAN-01 · 路径模式里的 `*` **只跨一层** ⇒ 嵌套 ≥2 层的目录**必然漏** ⇒ 「零命中」= **没查到**，不是 **不存在**

> **状态**：仍生效 · **核对日期**：2026-10-30 · **是否影响当前轮次**：是 —— 本轮用它决定了「哪些域要补指标抓取载体」。
> **证据**：2026-10-30 合并收口执行者自踩：扫 Go 真源各域观测端口时用 `ls service/*/rpc/etc/*.yaml` ⇒ ⇒ **漏掉 `service/user/user/rpc/etc/user.yaml` 与 `service/user/admin/rpc/etc/admin.yaml`**（这俩路径在 `service/` 与 `rpc/` 之间**隔了两层**）⇒ ⇒ 首轮结论「Go 侧有观测端口的 rpc 域 = 6/10」⇒ ⇒ **实际是 8/10**（`user-rpc 9094` + `admin-rpc 9097` 都有）⇒ ⇒ 若按首轮结论派工，这两个域会**被漏掉不补载体**（差 2 个域的偏离）。
> ⚠️ **同轮第二个坑**：macOS 自带 bash 3.2 **没有 `shopt -s globstar`** ⇒ `**/etc/*.yaml` 这类写法**直接报 `invalid shell option name`**（不是「零命中」）⇒ ⇒ 用 `find` / `glob` 工具而不是依赖 shell 的 `**`。

### 症状长什么样

- 你要回答「X 在哪些地方存在 / 不存在」⇒ 用一条**路径模式**扫 ⇒ ⇒ 输出很干净；
- ⇒ ⇒ **某些该命中的文件没进来**（因为路径深度不同）；
- ⇒ ⇒ 零命中 ⇒ ⇒ 你写下「**没有** / **不存在** / **不需要**」；
- ⇒ ⇒ **这个否定结论被拿去做了决策**（少派一条活、少补一个域、判一条「同形」）。

### 判定式

1. **凡要断言「某个东西不存在」⇒ 先问「我的枚举方式会不会漏掉某一类路径」** ⇒ ⇒ 尤其是**同一仓里深度不一致**的目录（本仓实例：多数域是 `service/<域>/<域>/…`，users 是 `service/user/<子域>/…` ⇒ **深度差一层**）。
2. **枚举「全量」⇒ 用目录树递归枚举，不要用「猜出来的路径模式」** ⇒ ⇒ `glob` 工具的 `**` 或 `find` ⇒ ⇒ **别用 `ls service/*/…`**。
3. **⚠️ `shopt -s globstar` 在 macOS 自带 bash 3.2 上不存在** ⇒ ⇒ `**` 写法会**报错**（`invalid shell option name`）⇒ ⇒ 别把报错当成「零命中」。
4. **零命中 ⇒ 必须有一句「我用的是哪种枚举方式 + 它覆盖了哪些路径」写在结论旁边** ⇒ ⇒ 否则下一个读台账的人无法判断这个「没有」是**查过没有**还是**没查到**。
5. **凡「否定结论」要拿去派工 ⇒ 先做一次交叉枚举**（换一个枚举方式再扫一遍）⇒ ⇒ 两个枚举方式的**结果集之差**才是真正要看的部分。
6. **反面：凡要断言「存在」⇒ 命中一个就够** ⇒ ⇒ 「肯定结论」对枚举完整性**不敏感** ⇒ ⇒ ⇒ **要命的只有否定结论**。

### 同族提醒

本条与「零命中是假信号」同族，但更具体：**零命中之所以假，是因为「没查到」被当成了「不存在」**；
⇒ ⇒ 检出手段也不同：不是「换一个更宽的判据」，而是「**把枚举清单打出来核对**」。
